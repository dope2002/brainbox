# 奇有此理｜微信小游戏开发包

首版采用微信小游戏 Canvas 客户端、CloudBase Node.js HTTP 云函数、PostgreSQL 与静态管理看板。客户端通过版本化业务 API 访问后台，平台能力、身份认证及数据访问分别适配，便于后续接入抖音小程序、App 和 Java 微服务。

包内文件

- [产品与技术规格](PRODUCT_AND_TECH_SPEC.md)定义产品范围、技术架构和验收口径。
- [开发与验收指南](docs/DEVELOPMENT.md)说明阶段交付、测试入口及多平台迭代方式。
- [题库管理与在线发布设计](docs/QUESTION_PUBLISHING.md)定义五种录题模板、审核上线、同步和验收。
- [迭代交接](docs/HANDOFF.md)记录当前进度、已验证结果和下一步。
- [新会话开发指令](CODEX_START.md)和[工程约定](AGENTS.md)供 Codex 接手使用。
- `reference/legacy-miniprogram/`：上一版微信**小程序**原型，仅供复用题库/判题/推荐逻辑。不能当作小游戏上线。

## 推荐使用

1. 在包含本 README 的工程根目录启动 Codex。
2. 在新会话中发送：“请按 CODEX_START.md 和 docs/HANDOFF.md 继续开发，完成后更新交接记录。” 如有具体迭代需求，在同一条消息中说明。
3. 审核 Codex 每个阶段的运行与测试结果；小游戏真机测试、真实 AppID/Secret 和生产 HTTPS 域名必须由开发者提供，不能在仓库里放密钥。
4. 五种题型具备测试样例后即可用隔离数据联调。发布灰度前验收 150 道人工审核题及真机链路，观察期结束后由产品负责人交付真实数据结论。

**特别说明：** 参考旧原型含64道未经正式人工审核的演示题。不因其存在就等于满足首版150道审核题的要求。

## 运行「山雾青」题流

在根目录执行 `npm test`。测试使用 Node 模拟微信 API，无需安装依赖或启动服务。

在微信开发者工具选择「小游戏 → 导入」，目录指向包含 `game.js` 的仓库根目录。AppID 选工具提供的小游戏测试号，或填写有开发权限的小游戏 AppID。可选「不使用云服务」，当前九道草稿题随包加载，覆盖五种交互。后台发题与线上同步已列入 P0，目前处于设计阶段。

首次进入会自动演示上滑换题、下滑回看。触摸可跳过教学，后续启动直接进入题流。阅读长题时，从正文起手滚动，从页头或正文两侧留白起手换题。第 4 至 9 题可检验文学长材料、历史排序、经济配对、哲学论证图、字形方阵和经学引文。[小屏布局对照](docs/prototypes/mist-layouts.png) · [验证与交接](docs/HANDOFF.md)
