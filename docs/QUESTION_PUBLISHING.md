# 题库管理与在线发布设计

## 交付目标

使用现有五种题型新增题目、修订题面和答案、更换已支持的题图或下架题目，均可在管理后台完成。一次发布后，已安装且支持该题目协议的小游戏通过版本同步接收更新。新交互类型或新媒体能力先由客户端支持，再由后台向对应版本发布。

以主规格 §3 的题目模型为准。历史、文学、经学、经济、哲学等内容分类独立于交互类型，运营可用同一模板录入不同学科的题。[产品与技术规格](../PRODUCT_AND_TECH_SPEC.md)

## 运营流程

| 动作 | 设计 |
|---|---|
| 新建或导入 | 选择题型后用表单录入，保存为草稿。支持按现有结构批量导入，按题号和字段返回校验结果。列表可按类别、题型、状态搜索或筛选。 |
| 编辑题面 | 通用字段包括分类、难度、题干、说明、分段材料、出处、解析和参考依据。表单因题型切换选项、排序项、方阵、点击区域或配对编辑区。后台生成稳定题号与内部选项 ID。 |
| 加图与预览 | 可录入题目自带的线索图、结构化作答区或上传普通题图。校验素材可用性、类型、尺寸和使用授权，支持替代文字。预览按小游戏实际版面展示题干、作答和答后解析，可检查小屏长材料、图示与命中区域。 |
| 审核与发布 | 结构校验通过后提交内容审核。审核人检查事实、出处、答案和配图，记录结论与时间。已有线上题可并行修改草稿，审核通过并发布后才替换线上版本。 |
| 快速下架 | 有权限的管理员从题目列表下架并记录原因。后续线上题库停止给出该题，客户端同步后从未展示的队列剔除。已打开的题卡可按当时版本完成。 |

### 五种题型的表单校验

| 题型 | 需校验的内容 |
|---|---|
| 单选 | 2 至 4 个选项，正确答案引用其中一个稳定 ID。 |
| 找不同 | 4×4 或 5×5 方阵，目标 ID 存在，审核确认唯一差异且可辨认。 |
| 排序 | 条目 ID 唯一，正确顺序完整覆盖条目，每项恰好出现一次。 |
| 点目标 | 目标图的坐标使用归一化矩形。区域有效且落在图内，答案引用有效区域，重叠或触控过小的区域由预览提示并在发布前修正。 |
| 拖动配对 | 左右各 2 至 4 项，每项恰好参与一次配对，两侧 ID 与答案映射一致。 |

## 发布和同步契约

- `question_id` 永久稳定。发布后的 `question_version` 内容固定，修订发布生成新版本。题干、答案、图示和解释随同一题目版本下发。回看、判题及事件归因保留实际看到的版本。
- `catalogRevision` 标识玩家可见的一次题库发布，独立于单题版本和客户端支持的 `schemaVersion`。发布或下架在同一事务内写入题目发布指针、审计记录和题库版本。写接口使用预期版本和操作幂等键，避免重复提交或覆盖别人新发布的内容。
- 客户端冷启动先使用最近一次通过校验的题库缓存，初次安装可使用随包审核题。在线时于启动、回到前台或题流预取前拉取 manifest，合并并发请求，版本一致时复用缓存。准备新题库期间，已打开的题卡继续作答。
- manifest 给出当前 `catalogRevision` 和协议兼容信息。题库接口按版本固定快照并支持游标分页，客户端只接收支持的题型、媒体和协议版本。暂时保留同步中的快照，版本失效时让客户端重查 manifest。任一必需分页失败时继续使用最近可用版本。完整校验通过后以新版本整体替换缓存和未展示队列，丢弃已过时的并发响应。
- 网络或图片加载失败时仍可离线答题。客户端对非关键图使用替代文字，对缺图便无法作答的题跳过本次展示。停用信息随同步生效，已知下架题在离线时也不再进入新队列。完全离线的设备恢复联网后才会收到新发布或下架信息。
- 普通图片通过后台上传到对象存储，以版本化 HTTPS 素材地址和尺寸、替代文字随题下发。运营预览和小游戏使用同一适配规则，小屏优先保证正文与作答区可用。线上快照只包含已审核、已发布、兼容当前客户端的题，草稿和测试素材单独隔离。

## 验收用例

1. 固定同一个兼容的小游戏构建版本，运营以后台页面新建一题。保存草稿、预览、审核并发布后，联网客户端在下次成功同步后显示它，正确判题并展示解析。整个过程无需更改或重新发布客户端。五种模板各跑一题，其中至少一题包含分段材料，至少一题包含上传的题图。
2. 编辑已发布题，发布前继续下发旧内容。发布后新卡使用新题目版本，已打开的卡和既有作答事件仍归属旧版。后台下架后，同步客户端的未展示队列和后续新批次都剔除该题。
3. 断网、下载中断、素材加载失败、两次并发发布和旧客户端遇到新能力题时，已有可玩题流继续可用。校验未授权账号不能发布、下架或通过公开题库接口读到草稿。
