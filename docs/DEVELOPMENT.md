# 开发与验收指南

先从[迭代交接](HANDOFF.md)找到当前任务、工作入口和已知缺口。功能范围、协议及指标定义统一维护在[主规格](../PRODUCT_AND_TECH_SPEC.md)；本指南说明如何分步实现和验证。

## 从当前仓库起步

在工程根目录可用 Node 直接运行旧原型基线，两项均无需安装依赖。

```sh
node reference/legacy-miniprogram/tests/test-engine.js
node reference/legacy-miniprogram/tests/test-page.js
```

第一项用于核对旧题结构、判题和选题行为。第二项用模拟的微信小程序页面检查首屏、作答和翻题等行为。迁移时从[参考引擎](../reference/legacy-miniprogram/utils/engine.js)和[题库原始数据](../reference/legacy-miniprogram/data/questions.json)着手。将旧答案索引转换为稳定 ID，保留旧题号，在阶段 0 的迁移记录中说明可复用逻辑、需重写部分和示例题的审核状态。

## 每阶段交付到哪里

| 阶段 | 本轮应能演示的行为 | 接手前可核对的证据 |
|---|---|---|
| 0 · 小游戏骨架 | 在微信开发者工具按小游戏导入，首题可作答，上下滑可切题 | 小游戏配置与入口、Node 模拟适配器测试、导入目录和实测结果、迁移记录。见主规格 §8 阶段 0 |
| 1 · 题型与内容 | 五种模板都有可玩的测试题。随包题、后台预览和在线题使用同一数据协议 | 题库校验命令、正反判题用例、手势验证和按模板的隔离夹具 |
| 2 · 运营发布与数据闭环 | 后台可录题并发布。小游戏同步新题，玩家操作经 HTTP 写入 PostgreSQL 后可在看板核对 | 固定小游戏构建验收后台发题。比较 100 名模拟玩家事件的预期指标与实际查询，覆盖离线、重复、部分成功、授权撤回和诊断快照 |
| 3 · 推荐与稳定性 | 跨会话分组稳定。下架题从新批次剔除，弱网仍可作答 | 缓存和版本兼容测试、连续 200 题内存观测、iOS/Android 记录、云端兼容性测试和部署回退说明 |
| 4 · 真实灰度 | 产品负责人可按观察窗口分析真实玩家行为 | 发布前核对 ≥150 道审核题、每种模板 ≥15 道，以及工程和真机验收；观察结束后另交真实数据结论，记录样本不足项 |

## 实现后的本地运行顺序

以下是工程需要提供的命令。首次接手先检查根目录脚本与 Compose 配置；各脚本落地后，将实际工作目录、运行时版本和必要的环境变量示例补入 README，并在交接记录中注明验证结果。

| 时机 | 从工程根目录执行 | 核对结果 |
|---|---|---|
| 客户端核心、测试题库已实现 | `npm run test`、`npm run validate:questions` | Node 模拟环境断言通过，非法题样例被拒绝 |
| 本地持久化已实现 | `docker compose up -d`，数据库就绪后执行 `npm run db:migrate` | 在独立开发库中完成迁移，重复执行保持数据一致 |
| HTTP 入口已实现 | `npm run dev:api` | 模拟登录取得业务凭证，用同一批事件重传两次，入库条数与看板结果一致 |

## 在线题库的开发顺序

1. 以 `src/interaction/types.js` 和现有草稿题为基线，定义五种题型 schema，补齐素材引用、状态和单题版本校验。先用模拟题库响应走通现有 Canvas，验证不同学科和长材料都能通过数据渲染。
2. 实现 PostgreSQL 迁移、题库读接口和管理鉴权。先完成一个单选题表单及预览，打通草稿保存、审核、事务发布、公开接口和客户端同步这一条链路。
3. 补齐四种题型表单、批量导入、题图上传与加载、编辑发布和下架。用真题结构的隔离夹具检查素材降级和版本切换，保留独立的线上审核流程。
4. 固定一个支持该协议的小游戏构建，用后台发布五种题，检查内容在同一构建中出现。记录题号、单题版本、题库版本、同步结果，并验证修订前后、离线恢复和下架。再在微信真机复测。

字段、运营流程和缓存故障处理见[题库管理与在线发布设计](QUESTION_PUBLISHING.md)。

## 后续迭代如何保持兼容

| 改动 | 同步检查 | 验证重点 |
|---|---|---|
| 在现有模板加题、修题、下架 | 后台表单、校验、审核、发布版本以及在线同步 | 固定客户端构建即可收到更新，旧版本事件仍归到旧版本 |
| 新玩法或媒体能力 | 题型注册、题库 schema、判题、渲染输入、兼容版本筛选 | 支持的客户端可以作答，旧版继续收到可玩的题 |
| 埋点或看板指标 | §5 的事件及分母、事件 Schema、离线队列、接收校验和聚合 SQL | 用固定样例同时断言首次与全部曝光；覆盖老客户端积压事件补传 |
| API 或数据库变更 | §6、OpenAPI、仓储、版本化 SQL 迁移和客户端调用方 | 用旧客户端请求及既有数据验证兼容，核对鉴权、幂等与错误码 |
| 新增抖音小程序或 App | 对接宿主界面、平台能力和身份验证器，沿用业务玩家 ID 规则 | 复用题型与 HTTP 契约测试，增加该平台生命周期、触控、断网和身份隔离实测 |
| 后端迁移 Java | 沿用版本化 API、会话和数据库约定；对同一固定数据比较只读结果 | 比对通过后逐路由切换；写入保持单一入口，回退后验证已写数据可读 |
